# Data

## What is here

`topk_results/` holds the top-10 recommendation lists that every recommender produced for
every user, as **item IDs only** (for example `[15851, 7146, ...]`). These are our own model
outputs and contain no third-party item text, so they are included in full: 4 datasets x 5–6
recommenders, seed 42. They were generated by `../recsys/evaluate_diversity.py` from the
checkpoints attached to the GitHub release; see [`../recsys/README.md`](../recsys/README.md).

## What is not here, and why

The processed datasets (`train.pkl`, `val.pkl`, `test.pkl`, `item_texts.pkl`) and the
pre-computed item-text embeddings are **not redistributed**. `item_texts.pkl` embeds item
titles and descriptions taken from the source corpora, and the Yelp Open Dataset licence in
particular forbids redistribution. Obtain the sources yourself:

| Dataset | Domain | Users | Items | Interactions | Source |
|---|---|---|---|---|---|
| MIND | News | 50,000 | 7,713 | 185,581 | https://msnews.github.io/ |
| Yelp | Business reviews | 99,165 | 56,696 | 2,173,523 | https://www.yelp.com/dataset |
| Amazon Books | E-commerce | 12,129 | 14,710 | 291,042 | https://cseweb.ucsd.edu/~jmcauley/datasets/amazon_v2/ |
| Amazon CDs & Vinyl | E-commerce | 15,592 | 16,184 | 414,228 | https://cseweb.ucsd.edu/~jmcauley/datasets/amazon_v2/ |

The counts are those of Table I in the paper, after the preprocessing described there; the
`n_users` and `n_items` fields in each `../recsys/configs/extended/*.yaml` match them.

## Expected layout

Once you have the sources, build this tree and point `DIVERSITY_ROOT` in
`code/experiment_config.py` (judge experiments) and `data.data_dir` in the recsys configs at it:

```
<DIVERSITY_ROOT>/datasets/
  mind/          train.pkl  val.pkl  test.pkl  item_texts.pkl  stats.json
  yelp/          train.pkl  val.pkl  test.pkl  item_texts.pkl  stats.json
  amazon_books/  train.pkl  val.pkl  test.pkl  item_texts.pkl  stats.json
  amazon_cds/    train.pkl  val.pkl  test.pkl  item_texts.pkl  stats.json
```

`train.pkl`, `val.pkl`, and `test.pkl` are user–item interaction splits keyed by contiguous
integer user and item IDs; `stats.json` records the user and item counts. `item_texts.pkl`
maps each item ID to its display text; that text is what the judge sees in the prompt, so the
numbering must match the IDs in `topk_results/`. `code/data_loader.py` is the reference reader
for the judge side, and `load_data` in `../recsys/train_fusion.py` for the recommender side.
